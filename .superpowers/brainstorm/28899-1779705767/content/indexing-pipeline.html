ADK Agent Design — What Each Agent Does

SchemaExtractorAgent
no LLM sequential
Tools
find_schema_files(repo)
parse_openapi(path)
parse_protobuf(path)
parse_graphql(path)
Output
FieldNode[] with:
name, type, nullable
endpoint, transport
schema_source_path
ConsumerDetectorAgent
tree-sitter parallel per field
Tools
grep_field_name(repo, name)
read_snippet(file, line, ±5)
get_function_context(file, fn)
Output
FieldUsage[] with:
file_path, line
surrounding_context
containing_function
SemanticProfilerAgent + BeliefExtractorAgent
Haiku · cheap ADK ParallelAgent
LLM reads (per field)
• Field declaration + docstring
• 10-line snippets per usage
• Test assertions (if any)
• Commit messages touching field
LLM answers
• unit (cents? dollars? ms?)
• domain (payment? medical?)
• invariants (always positive?)
• consumer belief confidence
DisagreementDetectorAgent
Sonnet · accurate ADK LoopAgent
Compares producer contract vs each consumer belief.
ADK LoopAgent: reason → verify → assign severity.
UNIT_MISMATCH · BEHAVIORAL_CHANGE → semantic (needs human interrupt)
TYPE_CHANGED · NULLABLE_CHANGED → mechanical (auto-fix)
⚡ Incremental re-index on push (key for scale)
Git diff → only changed files go through tree-sitter again
Only affected fields re-enriched by LLM
Temporal workflow: skip to step 2 with diff context
Result: PR analysis latency ~30s instead of ~10min full re-index
